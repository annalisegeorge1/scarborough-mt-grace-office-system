# Database Model — V160

The authoritative production schema is migration-controlled under `server/migrations/`.

The core relational model now covers users, roles, sessions, cases, case activity, case notes, applications and checklists, document metadata, correspondence, appointments, community matters, initiatives, partners, field visits, events/action items/attendance, resident feedback, service recovery, public content, automation/reminders, staff roster/absence/coverage/handover and the audit log.

References are centrally generated by PostgreSQL sequences for cases, applications and records. Browsers must not create official production identifiers.

Sensitive resident data is separated from the public tracker projection. Public tracking requires both the case reference and the contact information supplied on the enquiry and returns only the public status/update/next-step projection.
