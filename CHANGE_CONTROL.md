# Change Control Baseline

All production changes should have a named requester, owner, risk level, reason, testing evidence, approval status and rollback plan.

During pilot:
- Low-risk content/configuration changes may follow the approved normal workflow.
- Medium-risk functional changes require review and testing.
- High-risk changes affecting authentication, privacy, database records, tracking or file access require explicit management/technical approval and a tested rollback path.
- Emergency changes must be documented immediately after stabilization if prior documentation was impossible.
